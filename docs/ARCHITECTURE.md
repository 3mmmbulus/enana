# enana 架构 (Architecture)

enana 由三部分组成:

| 部分 | 在哪里 | 公开? |
|---|---|---|
| **本地客户端** (本仓库): 安装器、控制台命令、本地辅助服务 (`lib/api.sh`)、仪表盘界面 (`ui/`)、sing-box 配置生成 | 用户的电脑 (`~/.enana`) | 是, 开源 |
| **云端服务** `api.enana.cc`: 账号 (注册 / 登录 / 设备与会话)、同步存储 (只存密文)、套餐与权益、签名内容下发 | enana 的服务器 | 否 (私有) |
| **官网与下载** `enana.cc` / `install.enana.cc`: 一个介绍首页 + 一键安装命令 + 安装包 | enana 的服务器 | 否 (私有部署; 安装包本身与本仓库一致) |

## 本地客户端做什么 / 不做什么
- 做: 安装 sing-box 核心、规则集下载、配置生成与热生效、launchd 常驻、系统代理开关、按应用 / 网站分流、测速、流量统计、日志、仪表盘。
- **所有代理数据只在本机**: 服务器地址与密码、订阅链接、SSH 凭据、访问记录、流量统计从不上传。
- 本地辅助服务只监听 `127.0.0.1`, 所有接口要求自定义请求头 + 登录令牌, 密码类操作要求再次输入账号密码 (见 `docs/API.md`)。

## 云端内容 (为什么仓库里只有「基线」)
公开仓库只带最小可用的基线数据 (3 个必选规则集、几个 AI 服务的目录项)。持续维护的精选内容 (完整服务目录、规则库清单、应用推荐、英文译文) 在云端, 登录后下发:
1. 客户端向 `api.enana.cc/v1/manifest.json` 取清单 (需要有效的登录会话);
2. 清单带 ECDSA P-256 / SHA-256 签名, 客户端用内置公钥 `data/cloud-pub.pem` 验签 (可以放多把公钥以便换钥);
3. 清单里有内容包的 sha256 / 大小 / 序号 (序号不能变小 → 防回滚); 内容包解压前先检查文件名白名单, 再逐个检查格式;
4. 通过后原子替换 `~/.enana/cloud/content` 并重新生成配置 (失败自动回滚); 验签失败 / 格式不对 / 网络不通都保留旧内容, 不影响代理。
构建工具 `tools/build-content-bundle.sh` 是通用的 (测试用); 真正的内容和签名私钥不在本仓库。

### 云端内容里的服务器部署脚本
同一个签名内容包里还有 `vps/{lib,probe,provision,redetect}.sh`: 「添加自己的服务器」(SSH 一键部署) 时在用户的服务器上执行的脚本 —— 协议选择 (现在是 VLESS + Reality)、依赖清单、服务端版本与 SHA-256 校验值、配置生成 (每个公网出口 IP 一个入站) 都在里面。**本机只有 SSH 编排** (`lib/vps.sh`: 连接 / 主机指纹固定 / 经标准输入交给远端 `bash` / 解析协议行 / 临时核心验证 / 保存); 脚本不在公开仓库, 没登录就用不了, 云端换协议或升级服务端版本时本机不用升级。凭据 (密码 / 私钥) 只经 600 权限的临时文件交给后台任务, 任务结束即删, 从不进命令行 / 日志 / 同步 / 返回给前端。

## 固定出口分配 (不是「一个全局出口」)
固定出口 = `role=pin` 的服务器, 可以有好几台 (最多 32 台可以单独指定); 每个应用 / 网站 / 服务各走各的: `overrides.tsv` 第 5 列 (`target`) 指定走哪一台, 服务 (`svc-<id>` 选择器) 在核心里选。**「默认固定出口」只是「跟随默认」(`target` 为空 / 选择器选 `PIN`) 的那些项目走的那一台**。设计原则: 固定出口存在的意义是出口 IP 不变 (AI / 账号 / 交易所), 所以**任何会让它们换 IP 的操作都不能悄悄发生**:
- 总览: 仪表盘「服务器 → 出口分配」(`GET /api/exits`, `lib/exits.sh`) 列出每个出口上有哪些应用 / 网站 / 服务、谁在跟随默认、谁指定的出口已经不存在 (孤儿)。批量改派 (`POST /api/exits/move`) 和「钉住」(`/api/exits/freeze`: 把跟随默认的钉在当前默认出口上) 只改规则集 / 选择器, 不重启核心。
- 事前检查: 换默认固定出口、删除固定出口、把它改成别的角色 (以及删除含固定出口的订阅) 之前, 先算出谁会换出口 (`GET /api/exits/impact`), 仪表盘列出来让用户选「继续走原出口 (钉住)」或「改派 / 跟着换」; 后端同样守住 (`reassign=` / `freeze=1` / `accept_orphans=1`, 否则 `E_EXIT_IN_USE`, 什么也不改), 命令行 / 任务入口一样受保护。改派在配置事务里完成, 失败整体回滚。
- 默认出口是显式的持久化设置 (`$H/pin-default`, 随事务备份 / 回滚), 核心重启后按它校正; 不再依赖「文件里的第一个固定出口」。
- 孤儿 (指定的出口被删 / 改了角色 / 超出上限): **路由语义不变**, 仍退回默认固定出口 (没有固定出口时才直连), 但会被标出来: 界面徽标、总览的孤儿组、`环境状态变化 item=exit_orphans` 健康事件、终端控制台的提示。没有做成「找不到就拒绝连接」(fail-closed): 那会在订阅刷新删掉节点这类无人值守的场合直接断网, 需要一个新的规则集文件名 (`ovr-pinblock`, 同时要更新 TUN 助手的白名单、旧助手会整包拒绝), 留作以后的可选开关。
接口细节见 `docs/API.md`「出口分配」; 测试见 `tests/exits.sh` (后端 + HTTP, 用 `tests/fake-core.py` 假核心) 和 `tests/exits-ui.test.js`。

## 配置快照与云端同步
「配置快照」(`lib/snapshot.pl`) 是本机可跨电脑同步的配置的统一格式: 白名单里的文件 (服务器 / 订阅 / 策略 / DNS / 规则库选择 / 自定义解析 / 自定义测速目标 / 偏好 / 服务器记录) + 证书 + 少数几个设置 (语言 / 日志保留天数 / 访问日志 / 自动更新)。同一格式用于 **导出备份** (`GET /api/export`, 明文, 需再次输入密码) 和 **云端同步** (`lib/sync.sh`): 同步时先 gzip、再用「账号密码派生的密钥」AES-256-CBC 加密并附 HMAC-SHA256, 云端 (`sync_snapshots`) 只存密文。密钥只在登录时派生并保存在本机, 退出账号即删除。应用快照时只写白名单内的文件、丢弃不合法的节点行 / 文件名 / 设置值, 并走和其它修改一样的事务 (失败自动回滚)。
永远不进快照: 令牌 / 会话 / 设备编号 / 端口 / 代理总开关 / 开机自启 / SSH 凭据。

## 账号、设备与会话
- 账号 = 邮箱 + 密码 (PocketBase); 同一账号同一平台最多同时在线 2 台设备 (云端强制, 来自套餐 `max_devices_per_platform`)。
- 登录 → 云端建立会话; 本机每分钟的定时任务 (`enana tick`) 每 ~2 分钟发一次心跳; 被其它设备下线 / 改密码 / 过期 → 本机自动退出登录并关闭代理。
- 退出账号 = 关闭代理 + 令牌轮换 + 释放设备名额 + 删除本机的离线登录缓存 / 同步密钥 / 二次验证令牌。
- 敏感操作 (删除服务器、查看凭据、导出备份、清日志、下线设备、清除云端同步数据) 要在已登录的基础上**再输入一次密码** (密码用本机的「加盐 PBKDF2 校验值」验证, 不需要联网), 换到 5 分钟有效的二次验证令牌; 改密码 / 注册 / 登录 / 设备管理都在仪表盘里完成, 官网没有账号页。

## 为以后收费预留
- 套餐 / 订阅在云端 (`plans` / `subscriptions`); 本机用 `GET /api/plan` 展示 (功能表 `features.<key>.{tier,enabled,coming_soon}`), 界面从不写死「免费 / 付费」。
- 受限内容 (比如以后的官方线路) 只有云端核对订阅后才会下发, 客户端只是展示和合并节点; 官方节点的凭据不可查看、不可导出, 订阅过期后下次同步自动消失。官方节点来自服务器私有配置里的第三方订阅源列表 (订阅链接含令牌, 只在服务器上; 见 `server/README.md`); 客户端把它们单独存放在 `~/.enana/official.jsonl` (不进 `servers.jsonl`、配置快照、云端同步和导出), 只进自动线路池, 内容没变化时不重新生成配置、不重启核心。节点必须交给本地核心才能用, 所以这是权限控制而不是防拷贝 (DRM)。
